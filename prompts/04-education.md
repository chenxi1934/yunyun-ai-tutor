# Codex Prompt 04：教育垂类核心（结构化 + 班情驱动）

阅读原题、计划、Agent Core、Runner 的实际代码，检查 Git 状态。聚焦初二信息技术《循环结构》，对初中/大学保留显式学段选择并展示不同深度。

请实现：
1. Pydantic 的结构化 LessonPlan：学段、主题、45 分钟目标、教学环节和时间分配、2-3 个课堂示例（代码、用例）、3 道分层练习（基础/进阶/挑战，参考答案、用例、评分点）、预测错因。
2. 完整产出可以存为 JSON，并导出 Markdown/代码文件组合；单个项目/题目有稳定 ID 和审核状态，不能是一大段自由文本。
3. 支持教师粘贴文本、上传 JSON/CSV 班级练习数据。至少准备两套不同班级的种子数据，总共约 5-15 个工作区示例文件。
4. 学情事实必须先结构化解析，区分“5 人未交”“3 人 while 死循环”，不得假设是 8 个不同学生；保留数据依据和未知项。
5. 输出错因预警时必须包括 `misconception_type`、学情 evidence、trigger、cause、teaching_intervention、相关练习 ID；没有证据的结论明确标为预测。
6. 同一主题的两套班情必须导致具体的教学安排、练习强调或示例不同，不能只替换几句话；初中/大学学段的内容深度、术语和评分标准必须有实质差别。
7. 所有示例代码和所有练习参考解调用阶段 3 的真实 Runner；失败不得进入可交付候选，须保留失败与修复记录。
8. 教案文字、超纲风险、教学适配依然必须教师确认；代码 PASS 不能自动推导教学正确。
9. 可修订单个示例、练习或环节并重新验证必要的依赖。

实际执行测试：结构完整，时间总和为 45 分钟、3 档练习、示例数、全部参考解验证、两套班情差异、初中/大学差异、错因依据链、缺失/异常数据处理。用真实模型生成至少一次端到端结构化产出，记录模型失败/格式失败和修复方式。

更新 PROGRESS 与 ACCEPTANCE，说明具体可重现证据。不要做学生端聊天、教务系统对接或多学科泛化。
