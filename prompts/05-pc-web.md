# Codex Prompt 05：PC/Web 双端 + 权限审核 + 正式交付

开始开发前，请阅读：

- AGENTS.md
- docs/PLAN.md
- docs/PROGRESS.md
- docs/UI_GUIDELINES.md

前端实现必须遵循 UI_GUIDELINES.md。

重点是延续参考产品的视觉风格，同时突出

AI 编程 Agent 的工作区、代码验证和教师审核能力。

先复用已有组件，不做无关 UI 重构。

优先保证完整业务链路和功能验收。

检查 Git、原始题目、计划及现有实现。本轮直接完成完整双端闭环，并实际运行。

架构约束：React 同一套 GUI；Python/FastAPI 共享 Agent Core、教育逻辑、验证器与数据协议；PC 通过本地部署模式访问教师主动选择的真实目录；Web 通过沙箱工作区和隔离 Runner 访问内置示例。

PC 端 P0：

1. 提供 macOS（或 Windows）本机 `scripts/start-desktop.sh`/等效一键启动方式，能自动打开 GUI，README 写明 Python/Node 依赖。
2. 实际打开用户选择的本地工作区，展示真实文件树，创建/修改真实文件；只能在授权根目录内操作，防止路径穿越、符号链接外跳。
3. 对正式教案覆盖、已有题目删除、需要审批的命令展示修改内容和权限确认。审批必须关联具体文件版本/内容 hash，拒绝绝不能发生真实写入。
4. 可逐条接受/拒绝/继续修改教案部分、示例和题目；拒绝可回退，保存历史版本；修改代码后旧验证失效。
5. 支持会话恢复与所有教育 P0。

Web 端 P0：

1. 公开可访问的 URL（或按原题规定的受限替代交付），可由新浏览器打开。
2. 内置 5-15 个真实工作区文件及班情数据。
3. 一句话备课 → 结构化产出 → Python 真实验证（能展示故意失败）→ 学情预警 → 审核 → 可查看/下载教案包。
4. Web 不能读写服务器任意路径，也不能将服务端命令执行能力直接开放给浏览器；Runner 按阶段 3 隔离。
5. 页面优先信息可理解：执行进度、PASS/FAIL 证据、待审核、Diff 和文件导出。不要开发完整 IDE、登录、移动端。

必须验证：

- 用全新工作区重复 PC 主线，确认真实落盘；
- 本地正式覆盖被拒绝后文件字节不变，可恢复；
- Web 真正执行失败用例，再修复通过；
- Web 导出包含教案、示例、习题、评分点及验证报告；
- 重启/刷新后恢复会话；
- 分别演示两种学段和两套班情；
- 公网从不同浏览器访问端到端。

最后更新 README、PROGRESS、ACCEPTANCE，并给出可实际运行的启动/部署命令与已知限制。
