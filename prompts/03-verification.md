# Codex Prompt 03：真实 Python 验证闭环（最高优先级）

检查 Git 和相关上下文，仅改 Runner/Verification/Agent 相关必要位置。本轮要编码、写测试、真实运行。

交付目标：所有课堂示例代码与练习参考解都必须**真实执行并通过配套用例**才能进入“待教师审核的可交付候选”；失败必须显示哪段代码、哪条用例、什么原因。禁止 LLM 自评代替测试。

具体要求：
1. Pydantic 定义 `TestCase`/`VerificationReport`，记录 id、输入、expected、actual、stdout/stderr、exit code、耗时、错误、证据和代码 hash。
2. 实现 Python Runner：SyntaxError、Assertion/输出不匹配、RuntimeError、TIMEOUT、内部执行错误分别给出状态；超时能终止完整子进程树并清理临时文件。
3. 测试规格与待修复代码分离：Agent 能修改候选代码，但不能擅自删掉测试或放宽教师/固定基准用例，以换取 PASS。
4. Web 实际代码运行必须进入独立的受限执行环境：尽量无网络、非 root、限定 CPU/内存/pids、临时工作区、无越权宿主文件。不要把 Docker Socket 暴露给公网 FastAPI；若环境限制导致不能做到，先报阻塞与替代方案并给出可复现证据。
5. PC 不能在不提示风险的情况下直接运行未知不可信代码；本地 Runner 采用可用的隔离机制，普通 subprocess 只算有限防护。
6. Agent 在明确失败时可将错误日志加入上下文、最多重试 2 次修复候选实现并重跑；展示修复前后差异；达到限额后停并说明原因。
7. 任何代码/测试规格变更均使旧 PASS 失效；使用 hash 绑定验证报告；测试通过不代表教学内容可自动发表。
8. 验证结果能被 UI 正确区分，最终教案只包含符合规则的待审核候选；不能吞掉某些失败示例。

至少补充并实际执行 pytest 用例：
- 正确代码及参考解通过；
- 语法错误；
- 输出不匹配；
- while 无限循环超时；
- 边界条件失败；
- 执行异常；
- 代码变更使旧 PASS 失效；
- Agent 自动修复失败代码并在同一测试规格下重新通过；
- 无法修复时明确失败而不是交付；
- 跨目录访问、网络/命令能力符合隔离策略。

提交实际测试证据并更新进度/验收。严禁改断言、跳过测试、造假 PASS。
