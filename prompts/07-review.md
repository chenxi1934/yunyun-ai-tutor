# Codex 专项 Review（在阶段 2/3/5 后分别独立执行）

只进行代码审查，**不要修改代码**。检查当前 `git diff` 和涉及模块的实际实现与测试，重点不是格式、命名或无关重构，而是面试作品的 P0 功能缺陷与安全边界。

审查：
1. Agent 是否真执行工具并将工具输出回传模型？能否陷入无限循环、消耗无限额度或绕过审批？
2. 是否可能未运行测试就把生成内容标记 PASS？是否可能通过修改预期结果掩盖错误？变更代码后验证是否失效？
3. Python Runner 是否可能超时不停止，访问宿主文件、网络、环境变量？Web 容器是否具有危险权限？
4. PC 是否能路径穿越、符号链接跳出工作区？正式文件覆盖/删除是否实际审批？拒绝是否能回退？
5. 同班情是否只是替换 Prompt 文案、没有真实教学策略变化？证据是否对应实际输入？
6. 会话恢复是否保留了工作区、草稿、验证、审批而不只是聊天历史？
7. 测试覆盖是否存在重要假阳性？生产部署或桌面启动是否存在阻断问题？

只输出确实有证据的发现，按 P0/P1/P2 严重度排序；每个问题写出文件/行号、触发条件、用户后果、最小修复方案、应该增加的回归测试。没有证据的推测明确标注待验证。避免泛泛而谈。
