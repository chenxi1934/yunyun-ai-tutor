# Codex Prompt 06：最终对抗验收 + 提交材料

先执行 `git status`，阅读面试题全文、AGENTS.md、PLAN、PROGRESS、ACCEPTANCE、AI_DEV_LOG 和当前源码。

本轮停止功能扩张，只允许修复影响 P0、稳定性、安全性、演示的阻断缺陷。不要在没有验证的情况下给项目“全部通过”的结论。

1. 对照原始要求 A/B/C/D 和交付物逐项执行测试，逐项写入 `docs/ACCEPTANCE.md`：`PASS/FAIL/NOT_TESTED` + 实际证据（命令/日志/视频步骤）。
2. 重点对抗性检查：假 tool call、Mock 验证、死循环、错误标准答案、测试规格被 Agent 降低、hash 失效、超时后子进程残留、权限/路径穿越、敏感信息泄露、拒绝后仍写入、会话不能恢复。
3. 补充最小的 Playwright 端到端测试：Web 备课/验证/导出、审批拒绝；PC 的本地目录和启动流程用手工/可自动方式验证。
4. 真实调用一次模型，记下模型、API 用量和耗费（若能取得），清楚区分真实 API 与 Mock 模式。
5. 公网 URL 用全新浏览器测试；桌面一键启动在准备现场使用的机器上测试。
6. 完成 README：运行前提、环境变量、安装步骤、PC 启动、Web 部署、隔离限制、测试命令、Demo 流程、已知不足。
7. 在 `docs/AI_DEV_LOG.md` 记录至少一个真实 AI 失败→发现→修复→回归案例和关键 Prompt，不编造。
8. 将 `docs/DESIGN_DECISIONS.md` 压缩为真正的一页，覆盖：错误内容如何阻断/验证/留痕/确认；砍掉哪些非 P0 及理由；怎么使用 AI；未来学生端如何不变成抄作业工具；真实班级首个迭代与未成年人隐私/内容安全；源码引用。
9. 输出 ≤5 分钟演示逐秒/分段脚本，必须能拍到故意失败的真实运行、修复或阻断、班情错因、教师审核、本地落盘。
10. 输出最终提交清单：Web URL（若有）、Git 地址（需用户提供/授权）、视频链接（需用户上传）、一页文档位置、PC 启动命令、未通过的 P0。

修复 P0 缺陷后重复执行回归测试。严禁删除失败测试、扩大 Mock 掩盖问题、擅自部署或 Git push。结尾按“已通过/未验证/未满足/风险”总结，不声称尚未存在的链接已交付。
