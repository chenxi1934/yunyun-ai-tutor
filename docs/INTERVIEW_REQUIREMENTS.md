# AI Coding 面试题 ——「耘耘AI助教」

> 面向教育场景的类 Codex 编程助教（第一版聚焦教师备课）· 完成周期 48 小时

## 一、要你做什么

请做一个名为 **「耘耘AI助教」** 的产品：一个**面向教育场景的 AI 编程助教**，有桌面 PC 端和 Web 端。

它的技术形态对标 **Codex**（OpenAI 开源的本地编程 Agent）——能读写文件、改代码、跑代码、多轮对话。但它服务的第一批用户不是工程师，而是**教编程课的老师**；第一个要打穿的场景是**备课**。

请在设计中正面回答这个核心矛盾：

> AI 生成一份教案又快又像样，但课堂里它的一句话会被同时讲给 40 个学生听。
> 备课场景真正的价值不是"能生成"，而是**生成的东西能不能被验证、被追溯、被老师改**。
> 你的产品如何保证一个错示例、一段跑不通的代码、一道超纲题不会直接进课堂？

## 二、目标用户与典型场景

第一版服务对象：**信息技术/编程课教师**（初中信息学、大学编程课均可，请你自己选定一个学段并说明理由）。

请围绕这样一条备课链路来设计（这是你 48 小时里要跑通的主线）：

> 周三晚，初二信息课老师要备一节《循环结构》。班里刚学完条件语句，上次循环前置练习有 5 人没提交、3 人把 `while` 写成了死循环。
> 老师希望助教在十几分钟内产出一套**能直接拿去上课**的东西：教案（含教学目标、环节、时间分配）、2~3 个课堂演示示例代码、3 道分层练习题（基础/进阶/挑战，含参考答案与评分点），并预判这节课学生最可能踩的坑。

学生端对话辅导**本次不要求实现**，但你的设计文档里要说明将来怎么开放给学生（见第六节）。

## 三、必做需求（P0）

### A. Agent 技术底盘（对标 Codex，两端都要跑通）

1. 自然语言提出备课需求 → Agent 读写一个工作区（教案、示例代码、题库等一组文件）→ 生成或修改内容 → 以可感知形式呈现（新文件或 diff，老师可接受/拒绝/继续改）；
2. **能真实运行代码并拿到结果**——备课场景里判对错不能靠模型"觉得对"；
3. 多轮对话、保持上下文，支持会话恢复；
4. 接入至少一个大模型 API（通义 / DeepSeek / GLM / GPT / Claude 均可，**key 自备**，建议总花费不超过 50 元；允许保留 mock 模式兜底演示）；
5. 有明确的**权限分级**设计：哪些操作可自动执行（读教案、在临时目录跑代码），哪些必须老师确认（覆写老师的正式教案文件、删除已有题目）。

### B. 教育垂类能力（本题重点，请做实，不接受只在提示词里改改话术）

1. **备课产出结构化、可复用**：一次备课要输出结构化的教案 + 示例代码 + 分层练习题（基础/进阶/挑战三档，含参考答案与评分点）。建议用固定的 JSON / Markdown 协议，让产出能被老师逐条接受或回退，也能被后续统计，而不是一大段自由文本。
2. **正确性验证闭环（最关键的一条）**：所有课堂示例代码与练习参考解，必须**真的跑起来并通过配套用例**才能交付给老师；跑不通要明确说"哪个示例、哪条用例挂了"，禁止输出"这段代码应该没问题"。老师拒绝某个产出时，要能回退。
3. **错因预警（把学情前置到备课里）**：针对本节课知识点，Agent 要输出结构化的预判——学生最可能犯的几类错误（如：循环终止条件、变量作用域、边界取值、算法思路）、每类的触发原因、以及课堂上怎么提前干预。这些要和学段、上一节课的实际数据对得上，不能是通用套话。
4. **学段与班情适配**：可配置面向学段（如初中 / 大学），输出深度、用词、例子、类比要能体现差异；并允许老师粘贴或上传一份班级练习数据（格式自定义，建议给种子数据），让本次备课的侧重点由这份数据驱动，而不是每次都生成同一份教案。

### C. 桌面 PC 端（对标 Codex，本机真实可用）

- macOS 或 Windows 本机可运行（Electron / Tauri / Python 打包 / CLI + 简易 GUI 均可，形态不限，跑起来就行）；
- 能打开**老师本地真实的教案与题库目录**作为工作区，文件写入**真实落盘**；
- 执行命令、覆写文件前按你的权限分级策略请求确认；
- 上面 B 的四条能力以学生以外的视角——即老师视角——完整可用。

### D. Web 端

- 提供一个**可直接打开的 URL**；
- 工作区可用内置示例（一套预置的教案 + 练习题 + 若干份班级练习数据，约 5~15 个文件），写操作允许内存级/沙箱模拟，但 B 的四条能力必须真实可用；
- 至少覆盖这条链路：一句话备课需求 → 结构化产出 → 示例代码验证结果 → 落成一个可下载/可查看的教案包。

## 四、参考实现：Codex 开源代码

Codex CLI 是 OpenAI 完全开源的本地编程 Agent，Apache-2.0 许可，欢迎参考：

- 仓库：https://github.com/openai/codex （核心运行时在 `codex-rs/`，主体为 Rust）
- 官方工程博客《深入解析 Codex 智能体循环》：https://openai.com/index/unrolling-the-codex-agent-loop/

值得你提炼成自己设计的架构点（在上述博客和仓库中都有据可查）：

- **Agent Loop**：接收输入 → 构建提示 → 模型推理 → 执行工具调用 → 把工具结果追加回上下文再次推理，直到模型输出一条面向用户的助手消息才算本轮结束。一次备课可能循环几十次，"什么条件下该停"是你的核心设计；
- **上下文窗口管理**：对话越长提示越长，Codex 用压缩（compaction）在 token 超阈值时替换历史。一份长教案加上多轮改动很容易撑爆上下文，你打算怎么处理；
- **提示前缀一致性与缓存**：Codex 刻意保持"旧提示是新提示的精确前缀"以命中 prompt cache，中途改工具列表、改审批模式都会导致缓存失效。这是"能跑"与"跑得又快又省"的差距；
- **审批分级 + 沙箱边界**：读文件 / 改文件 / 执行命令分别要不要用户确认，命令在什么边界内执行；
- **会话持久化与 resume**：教案备到一半关掉，第二天接着备；
- **多宿主共享同一核心**：CLI / IDE / Web 复用同一个引擎——这直接决定你双端怎么架构才不重复干活。

**边界说明：**

- 请提炼**架构思想**，用你最熟悉的语言实现 mini 版即可。不要求 Rust，也不要求 fork Codex 代码——48 小时二次开发一个十几万星的仓库不现实，那也不是考察点；
- 如果你直接引用或改写了 Codex 及其他开源代码，请在《设计与教育判断》文档中注明出处和改动范围。如实标注不影响评价，隐瞒才会。

## 五、明确不要做（不加分，浪费时间）

账号注册体系、付费与会员、完整 IDE 功能（编辑器/调试器/插件体系）、多 Agent 并发编排、移动端适配、营销落地页、界面美观度打磨、对接真实学校教务系统、学生端对话辅导功能。请把时间花在**核心链路 + 教育垂类能力**上。

## 六、交付物

1. **可访问的 Web URL**（主推）。若国内网络难以稳定部署，可改为录制视频 + 说明部署方式；
2. **桌面端**：安装包，或写进 README 的"一键跑起来"启动命令；
3. **演示视频 ≤5 分钟**（作为兜底交付），**以备课场景为例**，完整走一遍：老师提出《循环结构》这节课的备课需求 → 助教产出结构化教案与分层练习 → **示例代码真实运行并通过验证**（这一段务必拍到，包括故意让它失败时的表现）→ 产出写入老师本机教案目录 → 呈现本节课的错因预警；
4. **源码仓库**（Git，保留完整提交历史与关键 prompt 记录）；
5. **一页《设计与教育判断》文档**，必须回答：
   - 你如何保证 AI 生成的错误内容不直接进课堂？验证、留痕、老师确认这几步你的边界画在哪里；
   - 你砍掉了哪些备课功能、为什么（48 小时你一定砍了东西）；
   - **你如何使用 AI**：关键 prompt 示例，以及 AI 产出错误或不满意时你怎么发现、怎么修正（至少 1 个具体例子，尤其是示例代码跑不通、错因预判是套话、教案写成空话这类问题）；
   - 这套东西将来开放给学生用时，你怎么防止它变成"高级抄作业工具"（只需设计思路，不要求实现）；
   - 如果要向真实班级上线，你的第一个迭代做什么（包括未成年人数据与内容安全的考虑）。

## 七、提交方式与现场环节

- 截止时间：收到题目后 **48 小时**；提交 Web URL + 仓库地址 + 视频链接 + 一页文档即可。
- 面试现场我们会给一段真实备课需求（例如："下周三给初二上一节《循环结构》，班里刚学完条件语句，上次练习 5 人没交、3 人写了死循环，帮我出这节课"），请你用做好的产品**当场**跑一次，并现场说明：产出里哪些是可信的、哪些需要老师把关、错因预警是否贴合这份班情。
- 桌面端请务必保证当场能跑。
