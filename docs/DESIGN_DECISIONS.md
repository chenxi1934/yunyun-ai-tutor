# 耘耘AI助教：设计与教育判断

面向初二教师的45分钟《循环结构》备课，先打穿“生成→真实验证→教师审核→落盘”；大学配置用于验证深度适配。选择初二是因为条件更新、零次循环和边界错误容易真实复现，班情能直接改变课堂行动。

**可靠性边界。** PC/Web共用串行Agent Core；模型只能读授权文件、提草稿、调用受限验证、请求审批；调用仅记用量，不设预算闸口。固定任务契约由服务端持有，候选容器不拿到expected；全部示例与三档参考解须逐用例真实通过。代码、规格、镜像、策略Hash共同绑定报告，修改后旧资格失效。文字、难度、评分、错因仍须教师逐项判断；代码PASS不能证明教育正确。正式创建/覆盖/删除另确认具体Diff，拒绝不写入；历史恢复形成新草稿。多文件中断保留日志和现场，教师对账后继续，不自动重放。

**班情与教学。** A班5人未交、3人死循环，交集未知，不能相加为8人；安排先修诊断与while变量追踪。B班0未交、0死循环、8人边界错误，转向range终点、n=0/1与边界评分。初中重变量追踪，大学增加不变量、终止性、嵌套循环和复杂度论证。预警区分观察、预测、病因假设并引用事实。浅紫白色工作台突出对话、工作区、逐项报告及审核，复用组件，避免装饰挤占任务。

**48小时取舍。** 只支持Python、循环结构、固定题目契约、单API worker与串行执行；砍掉账号付费、完整IDE、移动端、教务接入、多学科、学生聊天和多Agent。PC用本机服务+浏览器GUI、真实目录；macOS启动包自动准备隔离依赖。默认经HTTPS演示代理复用远端模型/沙箱，Key留服务器，本地审核落盘；独立模式仍可SSH。演示无应用鉴权，但保留限流、并发、超时、体积及隔离边界。本轮仍缺真实教师专业审核、现场确认和≤5分钟成片，不能称全部验收通过。

**如何用AI。** Codex协助实现与回归，百炼qwen3.8-max通过原生工具生成教案。关键指令：“所有课堂示例代码与练习参考解都必须真实执行并通过配套用例”；阶段Prompt及运行SYSTEM可查。真实案例：模型解释for时写“第6次条件判断时i=6”，但实际代码没有该判断；输出测试仍全过。逐段对照代码发现后，经修订接口改为range耗尽、i停在5，保留原稿/父版本，再重跑全部15程序/51用例。详见[AI开发记录](AI_DEV_LOG.md)，该审校不是教师批准。

**学生端与首轮上线。** 学生先提交思路/预测/尝试，再给局部诊断与递进提示；参考答案由教师控制披露，记录过程，作业模式限制整题代写。首轮只做教师小范围试点：仅接收去标识汇总数据、明确告知与访问权限、落实删除与保留期限、评估未成年人隐私和内容安全；补强沙箱与滥用防护，按教师反馈修正误导性讲解。当前未实现自动24小时清理，不把计划当能力。

**来源。** 架构参考[Codex Agent Loop](https://openai.com/index/unrolling-the-codex-agent-loop/)与[Codex源码仓库](https://github.com/openai/codex)（Apache-2.0），本项目未引入其源码；Python/React实现独立编写。HTTPS脚本下载并适配[acme-tiny](https://github.com/diafygi/acme-tiny)（[MIT](https://github.com/diafygi/acme-tiny/blob/main/LICENSE)），改动范围为IP标识、shortlived profile与SAN；其他库按依赖清单使用。
